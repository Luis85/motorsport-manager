# Native visual acceptance — finishing pass

This is an **engineering review**, not a user approval or human usability certification. It compares actual Godot renders with the original C01/C02/C03 hierarchy, and records domain-preserving adaptations. No new mockup was generated. Original boards and native-resolution crops remain reference artwork, not approved replacement screens or game facts.

## Evidence and decisions

C01 informs map/timing/two-car hierarchy and visible decision deadlines. C02 informs deliberate review/confirmation and action-to-service/intent feedback. C03 informs distinct practice, strategy, telemetry, weather, setup and results tasks. Native illustrated scenery, flat dot cars and original vector emblems are retained instead of photorealistic art or fabricated portraits.

The native comparison bundle pairs every SC family with its applicable original board and available d583 baseline. It includes unaltered source screenshots, source manifest and review sheets. Different scenario/time states are labeled: these are hierarchy comparisons, not controlled performance or lap-time comparisons. A missing corresponding baseline is explicitly marked rather than synthesized.

The `ui-finish-populated.json` report contains **149 captures / 655 assertions** over physical runs and validated snapshots. `ui-finish-details.json` adds **15 below-fold captures**, using native scrolling to expose weather cases/alternatives, practice costs, the second service card and measured sectors. Three canonical profiles are used for all screen families; primary screens also sweep all supported text preferences and both wide profiles. Synthetic receipt, stress, queue, missing-sample and style-state fixtures are labeled separately.

**Final revision found by visual review:** compact qualifying truncated its release boundary and used wording that could imply a current hot-lap countdown. Native red assertions reproduced both; the final two-line wording identifies a new release and elapsed-session boundary, with all 19 observation assertions passing. No remaining critical-action or identity defect was observed in the reviewed captures; that is not a claim that every possible game state has been manually inspected.

## State and contrast audit

The native production-theme fixture in `ui_finish_states_tests.gd` checks normal/hover/focus/pressed/selected/disabled, explicit unavailable/executing/stale/acknowledged labels, and cached resources at 100/115/130%. It includes a documented **4.5:1 local text-contrast engineering target** for the pairs it checks; the JSON values, not visual appearance alone, support that test. This is not comprehensive WCAG, Windows screen-reader or disability-access certification.

The compact review deliberately scrolls long analytical evidence. Clipped top/bottom portions of a scroll area are not missing controls: separate native captures show the relevant content after scrolling, with the command footer still fixed. Ellipsis remains acceptable in secondary table summaries that expose complete inspection text; it is not used to hide the reviewed driver or the critical qualifying release boundary.
