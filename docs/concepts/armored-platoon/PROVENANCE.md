# Armored Platoon asset provenance

All tank geometry, materials, semantic markers, terrain samples, scenario layouts,
mission text and policy values in this folder were independently authored for this
repository on 10 October 2026, with original depot policy and briefing additions
on 11 October 2026. That date also includes original exterior fittings and native
procedural material finishes for both tank studies. They use the repository's MIT license, reproduced
in `LICENSE`, which permits distribution, modification and browser-side storage
and caching while retaining its notice. No proprietary game files, extracted
models, textures, audio, screenshots or recordings are distributed here.

The M4 Sherman and Panzer IV names identify historical vehicle families. These are
original stylized studies, not measured historical reproductions or assets from
Call to Arms: Panzer Elite. The values in `content/catalog.json` are explicit,
unvalidated gameplay approximations. They are not verified historical engineering
data or measured reference-game balance.

Source lineage:

- `source/model-forge/examples/armored-platoon/*.batch.json`: original complete
  authoring and refinement transactions; the adjoining `.model.json` documents
  retain revisions. The refinement adds hatches, periscopes, handles, tow and
  lifting rings, weld seams, lamp guards, fender braces, tool clamps, exhausts and
  a rounded Sherman transmission cover. These details were authored independently
  with native Forge primitives, rather than extracted from another game's assets.
- `.model-bundle.json`: generated by Model Forge, imported by Scene Forge with
  observed revision and state guards; `workflow.json` and
  `refinement.workflow.json` retain execution receipts.
- `source/scene-forge/examples/armored-platoon/`: imported model library, battlefield
  placements, exact terrain vertex samples and guarded scene transactions.
- `source/scene-forge/examples/armored-platoon/exports/*.three.json`: Scene Forge runtime exports, with deterministic whitespace normalization
  by pinned Prettier 3.6.2; geometry, materials and hierarchy are unchanged.
- `content/visuals.json`: exports plus semantic bindings compiled from the imported
  source recipes by the public Model Forge kernel helper. Version 2 retains the
  required articulation, socket and hidden-volume bindings and carries bounded
  inline texture data. Its canonical base64 RGBA8 transport preserves every native
  exported pixel while reducing JSON overhead; native Three exports retain their
  numeric arrays. Compact serialization preserves the existing game-folder and
  standalone artifact budgets without reducing texture resolution or detail.
- `content/catalog.json`: authored gameplay source, three original scenarios.

Vehicle materials use the native, deterministic `forge-finish-v1` recipes for
painted metal, bare metal and rubber. Model Forge generates the 128 × 128 RGBA
color, tangent-normal and packed roughness/metalness maps; Scene Forge exports
those same resources. Sherman paint uses an original olive tint, and Panzer paint
uses an original three-color palette. The maps are generated from declared seeds,
scale and wear values, with no external texture or image licenses. They are not
photographs, scans or replicas of a reference game's paint schemes. The final
recipes use restrained wear after a fixed-camera visual review; the earlier
more heavily patterned version remains in model history.

These exterior studies contain 7,508 triangles / 213 visible meshes for the
Sherman and 6,572 triangles / 224 visible meshes for the Panzer. Native authoring
audits require UVs and bound geometry, materials and dimensions. Neither these
checks nor screenshots establish AAA quality or measured reference parity. The
models still lack interiors, crew, LODs, continuous track deformation and bespoke
UV-atlas painting; primitive UV seams and differing texture density remain limits.

The 11 October runtime terrain textures, sky colors, architectural
details and depot markings are generated by original engine code under the same
repository license; no reference imagery is embedded. Runtime synthesized audio is authored in the engine; it is not sampled
from the reference. Third-party runtime libraries retain their own notices in the
generated engine artifact.
