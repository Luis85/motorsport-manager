# World & Scene Editor surface

Mode: **Operate**. Extend the existing Littlewild paper, woodland ink, Georgia headings and Arial controls. The author edits a detached scenario pack while the current story remains owned by its engine. The browser surface is part of the existing scenario workspace.

The first viewport exposes the world/scene hierarchy, a selected scene's spatial layout, entity selection, and the full-pack actions. The grid is a measuring tool generated from canonical tile coordinates, rather than decorative artwork. A companion, building, resource or decorative prop can be selected and moved directly. Arrow keys move between cells; Enter activates the focused cell.

World forms expose names, descriptions, terrain rows and numeric resource counts. Scene forms expose parent and kind, numeric bounds, destination links, entry requirements, messages and pause events, and source bindings. Rendering controls choose a supported dimension/adapter and configure named embedded scene views (scene, role, anchor and size). Folded JSON sections retain advanced world, entity and initial-state settings. Companions have visual carried-item quantities and a supported-item chooser. Props choose an existing visual asset and one of its models; they carry no production or simulation authority.

A bound island projects its source world's actual coordinates. A bound interior projects the building's canonical floor dimensions and cells. Companion room positions are read-only; the existing building designer owns room geometry. Decorative props can be placed on that projected floor. Inventory changes still target the source entity rather than creating another copy.

The editor session owns revisions, atomic accepted entity edits and undo/redo. Pack import validates before replacing the draft; rejected imports retain the existing draft. Export writes a full pack, including catalogs and configuration. Review & play uses the existing replacement preview. Cancel returns to the same editor revision. Closing and reopening from the same library pack retains the draft. Opening a different pack after editing offers an explicit Cancel-focused replacement confirmation.

Desktop uses a hierarchy column and a spatial/properties column beside the inspector. At narrow widths the hierarchy becomes a native world/scene selector, content reflows to one column, and the tile map scrolls horizontally without shrinking labels. Buttons retain visible keyboard focus, disabled reasons and a 44px mobile target. Text selection, caret and scrollbars use the existing experience tokens.

Verification source: `source/verification/scene-editor-browser.ts`. The suite checks desktop and mobile layout, world forms, keyboard and direct placement, inventory history, typed link/rule/event controls, decorative props, bound interior creation, default rectangular and explicit-hole floor masks, island coordinate projection, atomic import rejection, full-pack export, retained-draft reopening, replacement-review cancellation and Cancel-focused deletion. Runtime browser checks launch the authored graph, record actual 3D prop asset construction, exercise cross-world connection review/commit/return, restore native checkpoints and cameras, and visit a canonical bound interior floor. Cross-world setup in those checks is an explicitly authored fixture. Actual browser captures and result counts are recorded with the integrated verification run, separately from this direction brief. No claim of human usability, screen-reader testing or representative-device performance is made by those automated checks.
