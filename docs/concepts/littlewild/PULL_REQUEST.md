# Littlewild: portable worlds, storytelling and developer tools

Littlewild now supports complete scenario changes through validated data: creature and visual catalogs, world configuration, authored scenes, interactions, rules and saved work travel together. The Office example runs Phil's sales, Marty's supply and Angela's fulfillment through physical tasks and inventories.

The World & Scene Editor authors nested levels, building interiors, islands, props, native entities, entry requirements and cross-world connections. Scene visits retain unfinished work and deterministic continuation. The 3D Creature Editor edits supported appearance, body parts, archetype tuning, future defaults and current companion values, with portable packages and reviewed application.

Buildings provide visitable floors, item/equipment production and freeform staged construction and upgrades. Terraform previews edit grass, water, elevation and plants. Data-driven friendly duels support autonomous triggers and player staging; quests and duels have independent persistent settings.

Presentation is replaceable through typed renderer factories, detached observations and validated intents. The basic implementation remains the default; pinned PixiJS and ExcaliburJS provide actual 2D rendering. Scenes choose 2D/3D and may embed another 2D scene as a minimap or panel. Editor exchange supports Tiled, LDtk, Blender/Godot glTF/GLB, Obsidian Canvas and Advanced Canvas. glTF exchanges static proxies and supported native placement data; animated geometry ingestion is outside that contract.

Storyboards connect narrative notes and cutscene shots across worlds. Revisioned timelines animate entities, poses and cameras through detached 2D/3D previews; scene entry events, timed cues and completion events use validated story actions and reviewed transitions. Actual p5.js sketches add deterministic animation presets without introducing another simulation clock. Engine JSON export carries complete inert implementation sources, canonical data and checkpoints, assets, schemas, licenses and a Godot mapping manifest for code generators. Automatic TypeScript-to-Godot gameplay parity is outside that export contract.

One editable balancing JSON drives default gameplay libraries, simulation rules, creature tuning, world generation and starting scenes. The workshop and typed CLI/SDK support validation, reviewed changes, seeded comparisons and bounded parameter sweeps. Asset-folder archetype identity remains authoritative, explicit pack overrides remain captured, and edits cannot rewrite committed work or active duels.

Quality fixes cover atomic settlement, reviewed-content identity, initialization, deterministic ordering, native/portable continuation, bounded CLI I/O and browser diagnostics. All fifteen inventoried compatibility modules pass strict typing, with a zero debt budget and no suppressions or module-size exceptions. Inward contracts, compiled adapter ownership and authored-data ownership are machine checked. The typed Node/browser toolbox exposes these capabilities to developers and coding agents.

Research uses verified Flecs, Bevy, EnTT and Excalibur sources, Game Programming Patterns, Godot, JSON Schema and the supplied Playtank text. Separate implementation and independent review agents apply the documented improvement plan. Final immutable-source verification and current CI identities are recorded in `VERIFICATION.md` and `delivery-manifest.json` after the combined acceptance run.
