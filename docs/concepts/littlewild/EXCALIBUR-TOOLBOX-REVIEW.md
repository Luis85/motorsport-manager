# Excalibur patterns for the Littlewild developer toolbox

Research date: 2026-10-03. Official `excaliburjs/Excalibur` sources were fetched through the connected GitHub API/file tools at commit `2c37dbd6fa4b94eebd0076d9cfd84b96f1aa8f2b` (main as inspected, committed 2026-10-02). This is targeted source research, not an engine benchmark or exhaustive audit. Read the existing [architecture research](ARCHITECTURE-RESEARCH.md), Littlewild ECS/simulation/command sources and scenario review boundary. Only this report was authored; no dependency, runtime change or build was made by this research task.

## Recommendation

Borrow Excalibur's approachable authoring surface: typed startup options, named scene lifetimes, inspectable ordered systems, fluent action construction and resource readiness. Implement those as a small developer facade over Littlewild's existing profiles, scenario reviews, compiled commands and fixed-step application owner. Retain native state v8, story/profile compatibility, actor-major order, RNG draw order and explicit structural visibility. Do not install Excalibur or rewrite the ECS.

## Boundaries that should remain different

- **Clock:** Excalibur's [main loop](https://github.com/excaliburjs/Excalibur/blob/2c37dbd6fa4b94eebd0076d9cfd84b96f1aa8f2b/src/engine/engine.ts#L1991) defaults to elapsed updates and optionally drains accumulated fixed-step lag before drawing. Littlewild already owns a `.1` simulation step, bounded debt and suspension policy. A developer `step(n)` should request exactly `n` accepted steps from the application owner, not install another timer or borrow Excalibur's catch-up policy. Equal accepted steps and commands are the reproducibility criterion.
- **Commit safety:** Excalibur's cited scene swap assigns `currentScene` before initializing/activating it. That source sequence is not a transactional rollback contract. Littlewild's reviewed pack identity, fresh reconstruction, context/profile checks and registry restoration remain the launch authority. Public diff/fingerprint fields alone cannot authorize a commit.
- **Ordering:** Excalibur runs phase-wide preupdate/update/postupdate passes. Littlewild has explicit system phases and actor-major orchestration; translating its systems to another execution order can change contention winners and RNG consumption. Only expose the existing order.
- **Trusted execution:** Excalibur supports engine plugins, custom action implementations and arbitrary action callbacks. Littlewild's imported authoring formats remain behavior-free JSON. Developer conveniences may reference compiled capabilities but cannot register imported executable code.
- **Resource state:** Generic `Resource.isLoaded()` tests truthiness of data, and loader progress increments in `finally` even when a resource fails. These passages establish readiness/reporting separation: use explicit status and errors in Littlewild diagnostics rather than inferring acceptance from payload truthiness or 100% progress.
- **World isolation:** Existing global world/library registries still imply a single active context. A scene/session facade must state that limitation; scene naming alone does not establish simultaneous independent worlds.

## Small delivery sequence and acceptance

1. Publish detached capability, configuration and schedule descriptions sourced from existing manifests. Include examples that show the current profile/scene review flow and rejection reasons.
2. Add a prepare-only typed setup/recipe surface over those descriptions, with strict data-only runtime validation and bounded step/repeat counts. Preserve domain command result semantics.
3. Bind launch, exact stepping, inspection and disposal to one developer session owner. Add asynchronous asset readiness only when real assets require it.

Acceptance should prove that preparing/describing/exporting recipes leaves canonical state and RNG unchanged; equivalent recipes with the same seed/profile yield the same canonical exports; invalid/stale previews and command failures leave the documented boundary intact; display refresh cannot advance simulation; replaced/disposed sessions cannot act through retained handles; and schedule descriptions match compiled IDs/order. Existing registered Littlewild checks, strict/typecheck, architecture policy and source/bundle identity remain the integrated gate. This research task did not run that gate or establish browser/device usability or performance results.

## Subsequent renderer implementation

The recommendation above describes the original developer-toolbox task. The later explicit renderer requirement adds pinned ExcaliburJS 0.32.0 and PixiJS 8.22.0 distributions behind the renderer registry. Littlewild uses their graphics contexts directly, retains its existing frame owner, and creates no Excalibur Engine or Pixi Application/Ticker. This extends the presentation boundary while preserving the reviewed command, scenario and simulation ownership described above. See [RENDERERS.md](RENDERERS.md) and [vendor provenance](vendor/RENDERER-VENDORS.md).

The combined independent review requires actual visible geometry and clean raw browser diagnostics, in addition to method/lifecycle assertions. A working adapter API alone cannot prove that a backend displays the scene correctly. Renderer preparation and scene composition must also release canceled resources, reject stale completion and restore the previous adapter on preparation or first-draw failure. Final evidence is recorded with the release checkpoint in `VERIFICATION.md`.
